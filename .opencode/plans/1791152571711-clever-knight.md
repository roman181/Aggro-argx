# Casino / ARGO Multiplayer Slot – Plan (Deutsch)

## 1. Ziel & Verständnis
Aktueller Stand: Single-File-App in `index.html` (1290 Zeilen) – Vanilla JS + CSS, Mobile-First, 5x3 Slot, 5 Paylines, Demo-Modus aktiv, weil Supabase-Credentials Platzhalter sind (`index.html:506-508`).
User-Wunsch: „Casino" auf Deutsch – interpretiert als: Projekt auf Deutsch verständlich machen, lauffähig + erweiterbar zum echten Casino.

## 2. Ist-Analyse (aus Exploration)
- **Architektur:** Alles in `index.html:1-1290`. Kein Build. Supabase via CDN (`index.html:9` + `index.html:503`). Tabellen erwartet: `profiles(id,username,balance)`, `daily_bonus_claims(user_id,slot,claim_date)`.
- **Features vorhanden:**
  - Auth Login/Register/Logout `index.html:582-648`, Session-Restore `index.html:1159-1165`
  - Slot: `initSlot()` `index.html:918-940`, `spin()` `index.html:959-1037`, `calculateWin()` `index.html:1080-1106`, Auto-Play 10 Spins `index.html:1231-1242`
  - Tagesbonus 06/14/22h à €5, 4h-Fenster `index.html:689-704`, Claim `index.html:729-774`
  - Ranking Top-50 + Realtime `index.html:860-915`
  - Demo-Modus mit localStorage + Hardcoded-Ranking `index.html:511,583-597,843-858`
- **Hauptprobleme:**
  1. Supabase nicht konfiguriert → kein echter Multiplayer
  2. Bilder sind Industrie-Renders (fil.png, deck.png 1.7MB, ko1-ko4), keine Slot-Symbole; nur remote via raw.githubusercontent.com `index.html:530-535`; `Arg.png` ungenutzt
  3. `renderRanking()` XSS via innerHTML `index.html:892-899`
  4. Balance-Update nicht atomar (Race) `index.html:982-986,998-999`
  5. `updateBonusUI()` Race + 1s-Polling `index.html:776-806,1278-1281`
  6. Doppelte Supabase-Einbindung, README nur Template, kein SQL-Schema

## 3. Empfohlener Ansatz (inkrementell, Single-File beibehalten)
**Phase A – Stabilisieren & Deutsch (kein Backend nötig):**
- A1: `index.html:506-511` Demo-Erkennung sauber + Hinweisbanner Deutsch
- A2: Bilder lokal nutzen (`deck.png` etc. lokal einbinden statt remote URL), `Arg.png` als Logo in Header einbinden, Lade-Fallback verbessern `index.html:933`
- A3: Security-Fix XSS in `renderRanking()` → textContent / escape, `index.html:873-902`
- A4: Bonus-Polling von 1s auf 30s + nur bei Änderung rendern; `loadClaimedSlots()` await-fix `index.html:776-806`
- A5: README.md Deutsch mit Anleitung + SQL-Schema für Supabase

**Phase B – Echter Multiplayer (optional, braucht User-Input):**
- B1: SQL-Migration `profiles` + `daily_bonus_claims` + RLS-Policies dokumentieren
- B2: Supabase URL/Key konfigurierbar machen, Demo/Prod-Umschalter
- B3: Balance-Update atomar via RPC / Transaktion statt client-seitig

**Phase C – Casino-Erweiterung (nur wenn gewünscht):**
- C1: Zweites Spiel (z.B. Roulette oder Blackjack) als neue `section-view` nach Muster `slotSection` `index.html:464-487`, Navigation `index.html:491-495`
- C2: Sound, Gewinn-Historie, RTP-Anzeige

Nicht empfohlen jetzt: Framework-Umbau, Server-Authority-RNG, Echtgeld – zu groß für diesen Schritt.
